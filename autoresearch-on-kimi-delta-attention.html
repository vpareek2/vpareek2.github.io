A one-day experiment

Over 24 hours, an autoresearch loop improved the training throughput of a six-layer Kimi Delta Attention model on an NVIDIA GB10 from 833 to 44,942 tokens per second. The final implementation narrowly exceeded a pinned baseline from FLA, the Flash Linear Attention library, which reached 43,937 tokens per second on the same workload and device. Its strongest observed run median was 45,058 tokens per second.

This is a deliberately narrow result. The model architecture, sequence length, precision, optimizer, data order, and KDA equations were held fixed. The loop was allowed to change only how the computation was implemented. Faster results that altered the mechanism, weakened its gradients, or failed the numerical checks did not count.

The more interesting question is how the implementation got there.

Why optimize KDA?

I originally encountered KDA while doing architecture research. KDA is an expressive linear-attention mechanism, but my initial training path on the DGX Spark was too slow for useful experimentation. An update took nearly 40 seconds. At that speed, the cost of evaluating an architectural idea was dominated by the implementation rather than the idea itself.

The practical solution was FLA. It provides training-ready implementations of linear-attention mechanisms and was the fastest complete KDA training path I could run on the device. I could have used it and continued with the architecture work.

THE MECHANISM

KDA in one minute

Standard attention keeps every earlier key and value available. KDA instead compresses the past into a fixed-size matrix—a form of working memory. Each token reads what that memory currently predicts and writes only the correction. A learned gate lets different memory channels forget at different rates. The result is a memory that continually edits itself as the model reads.

The recurrence is easy to express in PyTorch, but efficient training requires parallelizing it across tokens without changing the forward computation or its gradients. That gap—from a correct implementation to a hardware-efficient one—became the target of the experiment.

The algorithmic escape hatch was already known. DeltaNet’s chunkwise formulation groups tokens into blocks: memory still moves sequentially between blocks, while most of the work inside each block becomes parallel matrix multiplication. The Kimi Linear paper derives the corresponding chunkwise form for KDA.

This project did not invent that algorithm. Kimi Linear supplied the mechanism and formulation, while FLA supplied a strong implementation and the performance target. The experiment was whether an agent could turn those ideas into an exact, hardware-specific training path for the GB10—and optimize it far enough to compete.

Designing the autoresearch loop

Autoresearch was not a single prompt. It was a closed experimental system: the model proposed and implemented changes, frozen gates determined what counted, and a durable record carried evidence from one attempt to the next.

The agent owned the fast inner loop. I owned the objective and periodically reopened the global profile when a locally productive search stopped attacking the largest remaining bottleneck.

Codex and Prime-Agent supplied the execution harness, while /goal, the exactness gates, the matched benchmark, and the append-only ledger made the work recoverable and auditable. FLA remained a performance comparator; an independent PyTorch path was the numerical reference.

This division of labor held throughout the campaign: the agent was strongest at executing and evaluating concrete experiments. I was most useful when deciding whether it was still optimizing the right problem.
